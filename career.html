2025.01 ~ 2026.07
제품

단지 상가 매장의 결제 단말(POS)과 고객용 주문 키오스크. 주문 도메인이 입주민 앱·POS·운영툴 3개 클라이언트에 동시에 걸침

문제

같은 주문을 세 클라이언트가 각자 해석해 상태가 서로 어긋났고, 영수증이 출력되지 않거나 순서가 밀렸습니다. 카드리더·안면인식기 같은 주변기기는 브라우저가 직접 접근할 수 없어, 에이전트 팀과 프론트엔드가 각자 수기 문서로 연동 규격을 들고 있었습니다.

수행
  • 픽업오더 주문 상태 머신을 앱·POS 양쪽에서 정합하게 맞춤 — 접수·거부·자동거부·부분취소까지 전이 규칙 통일
  • 매장 PC에 상주하는 윈도우 에이전트가 로컬 루프백 HTTP로 노출하던 주변기기 연동 규격을 OpenAPI 스펙 한 벌로 단일화하고 타입·클라이언트를 생성
  • 주방용·고객용 영수증 출력 로직과 출력 누락·순서 밀림 해소, 주변기기 포트 예외 처리
성과
  • 양 팀이 수기 문서로 맞추던 경계가 스펙 한 벌이 되어, 규격 불일치가 런타임이 아니라 컴파일 단계에서 검출됩니다
  • 주문 상태 불일치와 영수증 출력 누락·순서 밀림 해소

수행
  • 코인세탁기는 입주민 인증(안면인식·카드) → 이력 조회 → 결제 → 기기 제어 전 구간을 담당하고 3개 저장소의 배포 순서를 통제

  • 관리자 앱의 네이티브 번호판 인식 결과를 운영툴 웹뷰와 연동해 순회 중 정기·방문·미등록 차량을 즉시 판별, 신고 누적 기준 블랙리스트 자동 등록 정책 구현
  • 쿠폰 전 구간 — 앱 쿠폰함 신설, 시설 예약·결제 시 적용과 최종 금액 자동 산출, 결제 취소 시 원복 처리, 관리자 발급 유형·정기 자동 발급
성과
  • 수작업으로 개별 설정하던 엘리베이터 연동이 자동 연결 흐름으로 바뀌어 단지 오픈 시 담당자 입력 항목이 줄었습니다

문제
