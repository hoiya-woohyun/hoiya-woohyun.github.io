      • 매장에 나가 재현해야 알던 규격 불일치를 로컬 컴파일 에러로 확인

      • 파일 기반 라우팅으로 바꾸고 권한 가드를 레이아웃 라우트에 통합해 화면 564개 중 495개에 일괄 적용
    • 웹뷰 호환성iOS 웹뷰에서만 틀어지던 뒤로가기 스택은 스와이프백과 앱 내 뒤로가기를 구분해 바로잡고, Android 물리 백버튼은 가장 나중에 연 바텀시트·모달부터 닫게 함 · 구형 앱의 safe-area 이중 여백은 앱 버전 기준으로 보정
      • iOS 웹뷰에서 화면 전체가 멈추던 동적 import 실패를 재시도·조건부 새로고침으로 자동 복구
    • 네이티브관리사무소 운영툴 웹뷰가 관리자 앱의 네이티브 차량번호 인식(ANPR) 결과를 받아 쓰게 하고, 웹 OCR은 인식 실패 때만 쓰도록 바꿈
      • 순회 중 카메라로 비추면 정기·방문·미등록 차량 즉시 판별
      • 인식 요청을 순서대로 처리하고 늦게 도착한 결과는 버려 이전 요청의 번호판이 표시되던 오류 해소

  • 빌드·CI 체계

    • 번들러 전환webpack(CRA) → Vite, npm → pnpm 3개 제품 전환

      • 오래 걸릴 때 21.1분 → 4.0분 (입주민 앱, 2025.10~2026.02)
    • 공용 설정사내 운영 콘솔 모노레포에서 앱마다 따로 두던 Vite·TypeScript·ESLint·Tailwind·Prettier 설정을 공용 설정 패키지로 모아, 앱은 가져다 쓰기만 하게 함
    • 품질 검사리뷰에서 눈으로 찾던 것을 CI로 넘김 — PR이 새로 만든 Dead Code는 Knip 리포트로, 타입 오류는 원인 줄 리뷰 코멘트로 · Vitest·Playwright 테스트 환경 구성

  • 인증 세션·운영 안정성

    • 세션 갱신API 클라이언트·파일 업로드·동기화마다 흩어진 토큰 갱신을 한 곳으로 모으고 갱신 요청 5초 시간 제한·일시 오류 최대 3회 재시도 적용
      • 갱신 응답 없음 오류 화면 로드 1,000건당 0.88건 → 0.02건
      • 화면 일부의 첫 조회 실패가 화면 전체 오류로 번지지 않게 격리
    • 관측성고객 문의가 들어와야 알던 장애를 Sentry 알림으로 먼저 인지 — 도입 뒤 쏟아진 신호는 「그 기능을 쓸 수 있는가」로 등급을 나누고 원인 단위로 묶어, 정상 업무 거절이 장애 알림에 섞이지 않게 함
