자기소개

  • 최근에는 사람이 매번 기억하고 판단하던 일을 기계가 대신하게 만드는 데 집중했습니다.
  • OpenAPI 스펙에서 타입을 생성해 수기 정의를 없앴고, ADR·LLM Wiki로 결정 근거를 사람과 AI가 함께 읽도록 정리했습니다.
  • 직전 회사에서는 웹팀 리드로 3개 제품을 런칭하며 CI/CD와 코드 리뷰 프로세스를 세웠습니다.

핵심 역량

  • 개발 품질 검증 자동화 프로세스 확립

    • OpenAPI 스펙 기반 API 명세 타입 자동 생성 체계 도입 — 4개 제품
    • CI에서 신규 미사용 코드·파일을 검출해 원인이 된 줄에 리뷰 코멘트 자동 게시 (Knip)
    • DeadCode 발생률 11.54% → 1% 미만

  • AI 기반 바이브 코딩 인프라 구성

    • ADR·SPEC·BUGS로 AI 문서 분류 및 규격 구성, 개발 문서 갱신 자동화 구축
    • 저장소별 에이전트 규칙 21건 중 18건, ADR 34건 중 31건 최초 작성
    • AI 접근 권한 세분화, 민감 정보 저장소 → CD 파이프라인 이관
    • 사내와 별개로 개인 작업 환경에 PreToolUse 훅 기반 셀프 코드리뷰 게이트 구현

  • 빌드·리소스 최적화와 Turborepo 공용 설정 체계 확립

    • CRA → Vite, npm → pnpm 3개 제품 동시 전환
    • 같은 장비 기준 빌드 262초 → 13초, 의존성 설치 230초 → 4초
    • 번들러·린트·타입 설정을 공용 config 패키지로 분리해 단일 소스화

  • Sentry 관측성 구축 — 사후 대응에서 사전 인지로

    • 에러 바운더리에서 리포팅 로직 분리, 운영상 무의미한 오류 필터링
    • 단지·사용자 태깅 및 샘플 레이트 조정으로 오류 발생 지점 즉시 식별
    • 장애 인지 경로를 고객 문의 접수에서 모니터링 알림으로 전환

  • 멀티 브랜드·멀티 클라이언트 구조 설계

    • 앱·웹·POS·사이니지 등 6개 제품 병행 담당
    • 건설사 브랜드마다 다른 단지 앱을 코드 한 벌로 서비스하는 구조 설계

  • 브라우저 밖 런타임과의 통신 경계 — 웹뷰 · 로컬 에이전트 · 현장 기기

    • 카메라·PDF 뷰어·전자서명·다크 테마 등 네이티브 기능을 웹뷰 브릿지로 연동. 상용 환경에서만 가능하던 스마트홈 연동은 환경 간 인증 방식 일원화로 전 환경에 개방
    • 브라우저가 직접 접근할 수 없는 카드리더·영수증 프린터·안면인식기는 매장 PC의 윈도우 에이전트를 거칩니다 — 양 팀이 수기 문서로 나눠 들고 있던 이 경계의 규격을 OpenAPI 스펙으로 단일화해 불일치를 컴파일 단계에서 검출
    • 코인세탁기·세대 호출 엘리베이터 등 현장 기기 제어와 Electron 데스크톱 앱(bastion 경유 SSH 터널·RDP 실행)까지 담당

성과
  • 6개 제품을 병행 담당하면서 디지털 사이니지 CMS와 현장 지원 데스크톱 앱은 초기 구축부터 운영 투입까지 단독으로 수행했습니다.
  • 단독 담당한 사이니지 CMS에서 운영 투입 후 4개월간 결함 87건을 처리하며 결함 해결 리드타임 중앙값 26.4시간 → 2.3시간, 결함 유입 월 39건 → 16건으로 줄였습니다.
  • self-hosted 러너에 직렬로 물려 있던 PR 검증 체인을 병렬로 분기하고 정적 분석 워크플로를 흡수해, 검증 워크플로 완료 시간 중앙값 8.1분 → 2.8분(상위 10% 구간 21.1분 → 4.0분)으로 단축했습니다.
  • 배포 자격증명을 개인 액세스 토큰에서 조직 GitHub App 설치 토큰 체계로 9개 저장소에 일괄 적용해, 담당자 이탈과 무관하게 만들었습니다.
  • 앱·웹뷰·POS·네이티브·현장 기기에 동시에 걸친 도메인에서 상태 머신과 연동 규격을 맞추고 배포 순서를 통제했습니다.
